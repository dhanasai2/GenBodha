## Project 2: Invoice Exception Handling — 3-Way Match

---
│  Current deterministic │      100%        │        $10,400       │
│  Missed-duplicate cost │      $94,000     │        $94,000       │
│  Human review cost     │       n/a        │           $15        │
* **Enterprise Reality**: A mid-market company processing 5,000 invoices/month sees ~900 exceptions (18% mismatch rate). AP teams spend 3+ days/month manually triaging these.
**Insight**: The current benchmark catches all generated duplicates, but still reports wrong non-duplicate resolutions. The cost model makes those errors visible without treating them as equivalent to a missed duplicate.
* **Real Cost**: One missed duplicate vendor payment = ~$94,000 average recovery cost.

---

### Slide 2: Three-Part Design Philosophy

1. **Zero LLM Arithmetic** — Quantity diffs, price drifts, and tax mismatches are computed 100% in Python. "LLMs should classify and write; not calculate."
2. **Asymmetric Error Cost Matrix** — Thresholds are tuned on total dollar loss, not F1. Missed duplicate = $94,000. Unnecessary human review = $15.
3. **First-Class UNSURE State** — When PDF OCR confidence is below 70%, the system explicitly abstains and routes to senior AP analyst with a pre-filled checklist.

---

### Slide 3: Pipeline Architecture Live Demo

* **Stage 1** — Structured invoice extraction with simulated OCR confidence (87.56% clean, 12.44% noisy)
* **Stage 2** — Deterministic 3-Way Match: Invoice × PO × GR (100% code arithmetic)
* **Stage 3** — Fuzzy Duplicate Detector + Subscription Trap filter
* **Stage 4** — Exception Classifier (8 categories + UNSURE abstention)
* **Stage 5** — Financial Cost Matrix optimizer (live slider demo in dashboard)
* **Stage 6** — Resolution Engine: ERP status + grounded supplier email draft

**Q: How does the system avoid hallucinating incorrect dollar amounts in emails?**
*A: All dollar amounts in emails are populated from pre-computed Python variables, never generated by the LLM from invoice text.*

**Q: What if a duplicate invoice has a different number?**
*A: Fuzzy matching on (supplier + amount + PO ID) catches same-PO re-submissions with confidence score 0.92.*
